# Troubleshooting FAQ — symptoms first, fixes second

Every entry below happened at least once during VM/ISO smoke (Sep-Oct 2026).
Deeper background lives in `docs/wiki-draft/04-troubleshooting.md`.

## GPU: amdgpu DMUB cold-boot loop (RX 7900 XT, Oct 2026, CONFIRMED firmware regression)

- Symptom: cold boot hangs in `Error queueing DMUB command: status=2` storm,
  preceded by `SMU: No response` + `Failed to power gate JPEG/VCN`. Warm
  reboots boot clean. Failed boots leave NO journal (hang before flush).
- Eliminated, in order: missing blobs (all present), `pcie_aspm=off` (loops),
  `amd_iommu=off` (loops), ReBAR off (loops), kernel 7.2 vs LTS 6.18 (both loop).
- Bisected: `linux-firmware[-amdgpu] 20260916` = bad, `20250708` = clean cold
  boot. Same family as drm/amd#4737 (SMU crashes, firmware 20251125).
- Live with it: pin the pair in `/etc/pacman.conf` under `[options]`:
  `IgnorePkg = linux-firmware linux-firmware-amdgpu`. Unpin after upstream fix.
- Recovery from a hung boot: hold power 5-10s, unplug + drain 10s, boot menu
  `e` + `module_blacklist=amdgpu` (framebuffer session, no accel).
- Upstream draft: `docs/upstream-drm-amd-coldboot-dmub.md` (needs board model
  + VBIOS to file).

## Install: archinstall JSON rejected

- `TypeError` in `SectorSize.parse_args` → a `size`/`start` has
  `"sector_size": null`. Must be `{"unit": "B", "value": 512}` everywhere.
- `KeyError: 'Percent'` → no `Percent` unit exists (B/kB/MB/…/sectors only).
  Give explicit GiB sizes; there is no fill-disk value.
- `EFI system part ESP not found` → fat32 partition needs
  `flags: ["boot", "esp"]`; `boot` alone is not recognized as ESP.
- Always validate: `python3 -m json.tool install/archinstall-desktop.json`.

## Install: disk / boot

- `/sys/firmware/efi` missing → VM booted BIOS. Switch firmware to UEFI/OVMF
  (virt-manager Overview, or the `<os firmware="efi">` XML snippet).
- `Boot0002 UEFI Misc Device: Not found` → UEFI works but no bootable media:
  attach the ISO to the CDROM and put CDROM first in boot order.
- `invalid configuration: root partition not found` → usually a stale clone
  (`luicipheros-install` reads `~/LuicipherOS` only; `LUICI_WORK=` overrides)
  or residue from interrupted runs (`wipefs -a /dev/vda`, VM only).

## Install: network / mirrors / keyring (live env)

- `could not resolve host` → resolver broken. The installer self-heals
  (`ensure_dns` via default-route gateway). By hand: `resolvectl dns
  <iface> <gateway>` (slirp gateway is `10.0.2.3`) + restart resolved.
- `failed retrieving ... Resolving timed out` on ALL mirrors → same DNS
  issue, not dead mirrors. Fix DNS, don't chase mirrors.
- Typo'd mirrorlines (`https;//`) → rewrite the file; the rebuild carries
  reflector so humans stop hand-editing it.
- `no servers configured` → stale all-commented mirrorlist; reflector
  refreshes it on boot in current images.
- `keyring is not writable` / `required key missing` → live keyring broken
  or absent. Rescue: temporarily `SigLevel = Never`, install
  `archlinux-keyring`, RESTORE SigLevel, `pacman-key --init --populate`.
  The installer now ensures a healthy keyring automatically.
- Hangs at `archlinux-keyring-wkd-sync` with no process → the timer unit
  doesn't exist in minimal images; `archinstall --skip-wkd` (our script
  passes it; the package is also in the live list now).

## Install: packages

- `target not found: lib32-*` → enable `[multilib]` in `/etc/pacman.conf`
  (archinstall JSON + bootstrap do this automatically now).
- `target not found` (others) → check `pacman -Ss`; Sep 2026 dropped
  `systemd-boot-pacman-hook`, `hyprland-qtutils`, `wlogout`. Drop + note.
- AUR step silently skipped → yay wasn't installed (chicken-and-egg);
  `ensure-packages.sh` bootstraps it via makepkg now.
- yay stops at menus despite `--noconfirm` → yay v13 needs
  `--answerclean/--answerdiff/--answeredit None` (in the script). PGP key
  imports still need a manual Y.
- `sudo` timestamp expires mid-build → keep-alive loop (see runbook) or
  the build aborts halfway; re-running is safe (`--needed` skips done).
- `cc1plus: Killed` → OOM in parallel LTO builds (<=3G RAM). Prefer
  `*-bin` packages (vicinae-bin, tabby-bin, yay-bin rule).

## Desktop: Hyprland loads wrong/empty

- "Autogenerated config" warning, no bar/binds → our Lua never linked:
  first launch writes its own `hyprland.lua`, which then BLOCKS stow.
  Bootstrap backs conflicts to `~/.config-backup/` and retries (re-run it).
- `unknown config key 'dwindle.pseudotile'` → key removed upstream; check
  current `ConfigValues.cpp`, don't guess from old guides.
- `hyprland.conf` vs `.lua` → 0.55+ is Lua-only (`hyprland.lua` +
  `require()`); `.conf` is ignored when `.lua` exists, legacy otherwise.

## Desktop: apps

- Tabby crashes `Cannot read properties of null (reading 'appearance')`
  → a shipped (even comments-only) `config.yaml` poisons first-run theme
  resolution. We ship NO tabby config (README only); vanilla defaults win.
- `tabby -e` (fuzzel/swaync/yazi-wrapper depend on it) → VERIFY on target.
- Vicinae also on Alt+Space → its own built-in default, not our bind
  (SUPER+Space is ours); disable in Vicinae Settings if unwanted.
- Flatpak upload with no file dialog → portal chain down (see runbook
  portal check). yazi-as-picker is opt-in (termfilechooser), GTK default.

## VM host issues (virt-manager/QEMU user session)

- No `/dev/kvm` in container → run VMs on the HOST, not in Docker.
- `kvm_amd: SVM disabled (by BIOS)` → enable SVM Mode in host BIOS.
- `virbr0: Package not installed` (no sudo) → use QEMU/KVM **user session**
  (slirp), not the system connection.
- Firmware fixed to BIOS → `edk2-ovmf` missing, or libvirt hasn't picked it
  up; XML `<os firmware="efi">` edit always works.
- Host freeze with VM+build+browser on 10G RAM → lower VM to 3G, close the
  browser during heavy steps.

## VM access (no clipboard on TTY)

- Reverse tunnel (recommended): host `sshd` on → guest
  `ssh -R 2223:localhost:22 user@10.0.2.2` (keep open) → host
  `ssh -p 2223 guest@127.0.0.1`. Full guide: `docs/wiki-draft/05-vm-access.md`.
- Silent SSH hang (even `-v`) = TCP accepted, endpoint dead; ladder:
  host port listening? guest sshd active? banner via
  `curl -v telnet://127.0.0.1:2222`?
